# UI Specification

> 版本：v0.3
>
> 更新日期：2026-08-13
>
> 状态：核心布局与交互规则已确认；用于指导静态前端原型，后续根据真实电脑端与 BOOX Leaf 5 验证结果迭代

## 1. 文档目的与范围

本文档规定 P0 学习应用的页面结构、交互规则和主要状态，不规定精细视觉风格。

- P0 的实际开发和验证环境是电脑浏览器。
- 文档同时规定面向 BOOX Leaf 5 的窄屏阅读布局，作为之后真机验证和 Android 包装时的目标。
- 页面以阅读 Markdown、浏览学习库、填写反馈为中心，不试图复刻完整的 Neo Reader 或 Obsidian。
- 颜色、字体、圆角、阴影等细节在实现静态原型时再做轻量决定，不单独创建 `DESIGN.md`。

## 2. 已确认的总规则

- Markdown 采用连续上下滚动阅读，不采用一页一页的电子书分页。
- 不显示“第几页 / 共几页”、章节页数、百分比阅读进度或阅读统计。
- 不提供书签功能。
- 自动续读只恢复最近打开文章的大致阅读位置，不显示为进度。
- 学习库采用 Obsidian 式树状文件夹交互，支持任意深度的文件夹 → 子文件夹 → Markdown 文件。
- 文件树显示真实文件名，例如 `00-学习计划.md`、`01.md`，不读取 Markdown 内部标题作为列表名称。
- 学习项目的文件整理仍以电脑端为主；电纸书只承担浏览、阅读和反馈。
- 界面避免动画、悬停依赖和复杂特效；关键操作必须有足够大的可点击区域。

## 3. 响应式布局

### 3.1 电脑宽屏

电脑宽屏使用左右两栏：左侧学习库，右侧阅读区。学习库可手动收起，收起后阅读区占满可用宽度。

```text
┌───────────────────┬─────────────────────────────────────────┐
│ 学习库   [收起]    │ [展开学习库]（仅侧栏收起时显示）           │
│                   │ 项目名 / 当前文件名                        │
│ ▶ yet-to-start    │ ─────────────────────────────────────── │
│ ▶ on-going        │                                           │
│ ▼ archived        │ Markdown 渲染后的阅读正文                  │
│   ▶ 阿德勒心理学    │                                           │
│     01_目的论.md   │                                           │
│                   │ 文末反馈区                                 │
└───────────────────┴─────────────────────────────────────────┘
```

### 3.2 BOOX 窄屏

BOOX 窄屏正常时采用单栏全屏阅读。用户需要浏览文章时，学习库从左侧覆盖约三分之二的屏幕宽度；右侧保留一部分当前正文作为阅读位置的参照，而不是切换到独立的全屏页面。

初版 CSS 断点可暂定为视口宽度不大于 `900px`；实际 BOOX 真机上根据 CSS 像素尺寸再校准。

```text
正常阅读
┌──────────────────────────┐
│                          │
│       Markdown 正文       │
│                          │
│                          │
└──────────────────────────┘

阅读控制面板
┌──────────────────────────┐
│       [学习库] [写反馈]    │
└──────────────────────────┘

学习库抽屉
┌──────────────────────────┐
│ ← 返回文章  学习库 │ 当前正文 │
│ ────────────────── │ 仍可见  │
│ ▶ yet-to-start      │        │
│ ▼ on-going          │        │
│   ▶ 维特根斯坦十讲   │        │
│ ▶ archived          │        │
└──────────────────────────┘
```

## 4. 学习库树

### 4.1 结构与默认状态

```text
▶ yet-to-start
▶ on-going
▶ archived
```

- 第一次进入学习库时，所有文件夹默认全部折叠。
- 点击任意文件夹行，切换其展开或收起状态；不能只依赖小三角图标作为触摸目标。
- 点击 Markdown 文件行，打开该文章。
- `00-学习计划.md` 与普通文章一样作为文件行显示，不隐藏、不自动打开。
- 当前正在阅读的文章在其可见时使用灰底或左侧粗线等非颜色唯一标记突出显示。
- 如果应用启动时恢复了一篇文章，不强制展开其父文件夹；用户仍可按自己的文件树状态浏览。

### 4.2 展开状态

- 用户已经展开的文件夹，在关闭再打开学习库时保持原状。
- 该状态属于当前设备的 UI 偏好，不写入 Markdown，也不属于学习数据。
- P0 可使用浏览器本地 UI 存储保存该偏好；不要求同步到其他设备。

### 4.3 BOOX 学习库抽屉

```text
┌─────────────────┬────────┐
│ ← 返回文章 学习库 │ 当前正文 │
├─────────────────┤ 仍可见  │
│ ▶ yet-to-start   │        │
│ ▼ on-going       │        │
│   ▶ 维特根斯坦十讲 │        │
│ ▶ archived       │        │
└─────────────────┴────────┘
```

- 用户从阅读控制面板点击“学习库”后，打开左侧抽屉；抽屉宽度暂定为可用屏幕的约 `68%`，并占满高度。
- 右侧露出的当前正文只用来保留阅读上下文；点击该区域关闭抽屉，不应同时滚动或操作正文。
- 选择 Markdown 文件后，立即关闭抽屉并打开该文件。
- 点击“返回文章”不改变当前阅读文章和位置。
- 抽屉不使用滑动或淡入淡出动画，以适应电纸书刷新。

## 5. 电脑端阅读页

- 阅读区显示当前项目名与当前文件名，帮助用户在多个项目之间辨认位置。
- 学习库和文章正文各自独立滚动；滚动文章不应带动左侧文件树。
- 侧栏展开时显示“收起学习库”控制；收起后，阅读区提供“展开学习库”入口。
- 不做多标签页、文章标签栏、上一页/下一页按钮或文件编辑器。
- Markdown 正文之后紧跟反馈区。

## 6. BOOX 阅读页与控制面板

### 6.1 正常阅读状态

- 正文默认占满应用可用空间，不常驻显示复杂工具栏。
- 不常驻显示当前小节标题、页数、章节内进度或全书进度，避免滚动时遮挡正文。
- BOOX 的时间与电量属于系统信息，网页应用不重复绘制，也不请求设备电量。
- 页面右上角不放书签。

### 6.2 唤出菜单

- 用户在正文阅读区的下方四分之一、中央区域进行一次短按时，显示阅读控制面板。
- 手指拖动以滚动文章时，不应误触发菜单。
- 文末反馈输入框本身的点击不触发菜单。
- 点击正文空白区域、完成一个菜单动作或再次轻点触发区域后，菜单可关闭。

### 6.3 菜单动作

| 按钮 | 结果 |
| --- | --- |
| `学习库` | 打开左侧约三分之二宽的学习库抽屉，右侧保留当前正文；点击右侧或“返回文章”关闭。 |
| `写反馈` | 自动滚动到文章末尾的反馈输入框，并让输入框获得焦点，便于调用 BOOX 系统语音转文字。 |

P0 不在该菜单中提供目录、书签、翻页、样式设置、刷新模式或阅读统计。

## 7. 启动与自动续读

### 7.1 启动状态

| 条件 | 页面结果 |
| --- | --- |
| 尚未选择学习库 | 显示简洁的“选择学习库”页面和一个主按钮。实际采用系统文件夹选择器还是手动路径，仍由后端实现方案决定。 |
| 已选择学习库且上次文章仍存在 | 自动打开该文章。 |
| 已选择学习库但没有上次文章 | 显示学习库。 |
| 上次文章已被删除或学习库不可访问 | 显示原因，并提供进入学习库或重新选择学习库的入口。 |

### 7.2 自动续读规则

```text
用户停止滚动文章
  → 前端保存当前文章与滚动比例
  → 后端写入本机 JSON 配置

下次打开应用
  → 前端读取最近文章与滚动比例
  → 读取并渲染 Markdown
  → 渲染完成后恢复到接近上次离开的位置
```

- 自动续读只保存一个“最近打开文章”的位置。
- 它不是书签，不允许用户建立多个标记点。
- 外部大幅修改 Markdown 内容、改变设备视口或以后调整阅读排版后，恢复位置可能只接近原位置；P0 接受此限制。

具体 API 与配置数据以 `docs/DATA_MODEL_AND_API.md` 为准。

## 8. 文末反馈与生成状态

### 8.1 反馈区

```text
────────────────────────────
学习反馈

[ 说说你理解了什么、哪里卡住了，或希望下一篇怎么继续…… ]

[ 提交并生成下一篇 ]
```

- 反馈区始终位于 Markdown 正文末尾，不直接编辑正文其他部分。
- 输入框支持普通键盘和 BOOX 系统语音转文字。
- 空反馈不能提交。
- 用户点击“写反馈”只负责跳到这里，不会自动提交或生成。

### 8.2 生成中、成功与失败

| 状态 | 页面行为 |
| --- | --- |
| 生成中 | 禁用提交按钮，显示“正在保存反馈并生成下一篇……”。 |
| 生成成功 | 清空输入框；停留在当前文章；显示下一篇文件名，并提供非自动的“打开下一篇”入口。 |
| 生成失败，但反馈已保存 | 明确显示“反馈已保存，下一篇生成失败”；保留可重试入口，避免用户再次手动输入同一份反馈。 |
| 生成失败，反馈未保存 | 显示失败原因；保留输入框文字，允许用户修改后重试。 |

无论生成成功或失败，都不把当前文章标记为“已完成”。

## 9. 加载、空与错误状态

- 正在读取学习库：在学习库区域显示简短“正在读取学习库……”。
- 文件夹为空：显示“该文件夹暂无 Markdown 文件”。
- 正在打开文章：阅读区显示“正在打开文章……”。
- 文章读取失败：显示原因与“返回学习库”入口。
- 不使用骨架屏动画、旋转复杂加载器或依赖颜色的状态提示。

## 10. 视觉与电纸书约束

- 以黑、白、灰为主，颜色不是唯一的信息载体。
- 不使用动画、转场、视差、视频、渐变或悬停才出现的控制。
- 点击目标保持足够大，BOOX 上的操作行与按钮优先整行可点。
- 文章正文优先获得屏幕面积；工具栏和状态信息保持极简。
- 阅读排版使用一套固定 CSS 预设；P0 不提供字体大小、行距或字间距的应用内调节面板。后续可从用户选定的 Obsidian 主题中手动移植与正文阅读有关的 CSS 规则。
- 初版不要求模仿 Neo Reader 的精确样式，只借鉴“平时安静阅读、需要时唤出控制”的交互节奏。

## 11. 不在本 UI Spec 中实现的内容

- 书签、多书签列表或书签同步。
- 分页、页码、章节页数、总页数和百分比进度。
- 阅读时长、完成状态、学习统计和报表。
- Neo Reader 的目录、刷新模式、字体调节、自动翻页，以及应用内排版设置面板。
- 中途问答历史或常驻 AI 聊天窗口。
- Android 系统级时间、电量或按键控制。

## 12. 静态前端原型的验收点

在接入后端前，使用假数据完成以下可点击原型：

1. 电脑端能展开/收起学习库树，并打开一篇假 Markdown 文章。
2. 电脑端能收起/展开学习库侧栏。
3. 窄屏模式下能从阅读页唤出“学习库 / 写反馈”菜单。
4. 窄屏模式下“学习库”打开约三分之二宽的左侧抽屉，正文仍在右侧可见且可点击关闭；“写反馈”跳到文末输入框。
5. 文章阅读区、反馈区、生成中/成功/失败状态均有可见的静态演示。
6. 页面不显示页数、书签或面向用户的阅读进度。

静态原型通过后，按 `docs/DATA_MODEL_AND_API.md` 的第一条功能链，用真实 `GET /api/library` 与 `GET /api/article` 替换假数据。
