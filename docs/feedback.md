## 需求整理与优先级判断

> 判断口径：P0 是继续长期使用前需要优先确认或修复的问题；P1 是直接改善“阅读 → 反馈 → AI 生成”学习闭环的功能；P2 是有价值但不影响核心学习闭环的增强功能。

### P0：先确认和处理

1. **耗电过快**：一个半小时消耗约 15%–20% 电量。先排查是网页刷新、WebView、网络请求、滚动监听还是 BOOX 系统设置造成，再决定具体优化方案。

### P1：下一轮优先实现

2. **悬浮反馈框**：反馈入口可以在文章任意位置打开；悬浮框与底部输入框共享同一份草稿，关闭时不删除，只有保存或手动清空后才清除。
3. **选中句子并添加批注**：选中文章中的句子，记录用户的解释或疑问，并在提交反馈、生成下一篇时一并交给 AI。
4. **“不懂”高光**：用波浪线标记不理解的句子，并与批注绑定；没有写出具体疑问时，也能把该句直接作为下一篇的解释重点。
5. **文章位置指示器**：在右侧增加细小的阅读位置指示，帮助判断当前读到文章的大致位置，不先做复杂的阅读统计。

### P2：核心闭环稳定后再做

6. **“喜欢内容”高光与导出**：用浅灰背景标记喜欢的句子，并支持后续统一导出；它主要用于积累内容，不直接决定下一篇课程路线。
7. **阅读时间热力图**：记录每天的阅读时长，并用类似 GitHub 的热力图展示；它属于学习统计和复盘功能，不作为生成下一篇的前置条件。

### 分阶段实现原则

“选中句子”“不懂高光”和“喜欢内容高光”可以共用一套文字选择工具，但分两阶段实现：先支持“不懂句子 + 批注 + AI 上下文”，再加入“喜欢内容高光 + 导出”。这样可以先改善实际学习，而不一次性引入完整的高光管理系统。
